# Monorepo: Expo RN with Web SSR/CSR

A monorepo containing React Native modules built with Expo, designed to be embedded into native Android and iOS applications. Modules are distributed via a local Verdaccio npm registry.

## 📋 Setup Order (For New Team Members)

**Follow this order when setting up for the first time:**

1. **✅ This Monorepo** (set up first) - Start Verdaccio and publish packages
2. **Native Android App** (set up second) - Depends on Verdaccio running
3. **Native iOS App** (set up third) - Depends on Verdaccio running

> **⚠️ Important**: The monorepo must be set up and Verdaccio must be running before setting up the native apps.

## 🏗️ Generating iOS SPM Packages from Scratch

This monorepo includes scripts to generate Swift Package Manager (SPM) packages for React Native Runtime and module frameworks. These can be distributed and used in any iOS Xcode project.

### Prerequisites

Before generating SPM packages, you need to set up the React Native source project:

1. **React Native Source Project** (`rn-runtime-source/RnRuntimeSource/`)
   - Must be a React Native 0.81.5 project
   - Must have `ios/Podfile` configured
   - Must have CocoaPods dependencies installed

### Setup Steps

```bash
# 1. Navigate to the React Native source project
cd rn-runtime-source/RnRuntimeSource

# 2. Install npm dependencies
npm install

# 3. Install CocoaPods dependencies (CRITICAL - this takes 10-20 minutes)
cd ios
pod install
cd ..

# 4. Return to monorepo root and generate SPM packages
cd ../..

# Generate React Native Runtime SPM package
npm run framework:ios:spm:runtime

# Generate module framework SPM packages
npm run framework:ios:spm:products
npm run framework:ios:spm:cart
npm run framework:ios:spm:pdp

# Or generate all modules at once
npm run framework:ios:spm:all
```

### What Gets Generated

The scripts generate production-ready SPM packages in `frameworks/ios/`:

- **`ReactNativeRuntime/`** - Complete React Native 0.81.5 runtime
  - Includes Hermes JavaScript engine
  - Device + Simulator support (ios-arm64, ios-arm64_x86_64-simulator)
  - All React Native headers and libraries
  - Ready for distribution

- **`ModuleProductsFramework/`**, **`ModuleCartFramework/`**, **`ModulePDPFramework/`**
  - Pre-bundled JavaScript modules
  - Swift wrapper APIs
  - SPM-ready with correct resource paths

### What the Scripts Require

The generation scripts automatically check for:

- ✅ `rn-runtime-source/RnRuntimeSource/` directory exists
- ✅ `rn-runtime-source/RnRuntimeSource/ios/Podfile` exists
- ✅ `rn-runtime-source/RnRuntimeSource/ios/Pods/` directory exists (created by `pod install`)
- ✅ `rn-runtime-source/RnRuntimeSource/ios/Pods/Pods.xcodeproj` exists
- ✅ `rn-runtime-source/RnRuntimeSource/ios/Pods/hermes-engine/` contains Hermes xcframework

If any are missing, the scripts will show clear error messages with instructions.

### Distribution Package Contents

When distributing this monorepo for SPM generation, include:

**✅ Include:**
- `rn-runtime-source/RnRuntimeSource/` folder structure
- `package.json` (with React Native 0.81.5)
- `ios/Podfile` (CocoaPods configuration)
- `ios/Podfile.lock` (optional, but ensures consistent versions)
- `scripts/` directory (generation scripts)

**❌ Don't Include (will be generated):**
- `node_modules/` (run `npm install`)
- `ios/Pods/` (run `pod install`)
- `ios/build/` (build artifacts)
- `frameworks/ios/` (generated by scripts)

### Important Notes

- **`pod install` is critical** - It builds all React Native dependencies, creates the Pods.xcodeproj with all schemes, and builds the Hermes engine xcframework
- **First run takes 20-30 minutes** - Building React Native from source and installing pods
- **Subsequent runs are faster** - Scripts skip already-built schemes
- **Production-ready** - Generated xcframeworks support both physical devices and simulators

For detailed integration instructions, see `frameworks/ios/QUICK_START.md` and `frameworks/ios/INTEGRATION_GUIDE.md`.

### 📦 Distributing SPM Packages

The generated SPM packages use **relative path dependencies** for `ReactNativeRuntime`. This means module frameworks depend on `ReactNativeRuntime` using:

```swift
.package(path: "../ReactNativeRuntime")
```

#### Distribution Options

**Option 1: Maintain Directory Structure (Recommended for Local/Team Distribution)**

When distributing SPM packages, you **must maintain the directory structure**:

```
frameworks/
└── ios/
    ├── ReactNativeRuntime/          ← Required base package
    ├── ModuleProductsFramework/     ← Depends on ../ReactNativeRuntime
    ├── ModuleCartFramework/         ← Depends on ../ReactNativeRuntime
    └── ModulePDPFramework/          ← Depends on ../ReactNativeRuntime
```

**How to Distribute:**
1. Copy the entire `frameworks/ios/` folder to your distribution location
2. Ensure all packages remain in the same relative structure
3. Consumers add packages via Xcode: **File → Add Package Dependencies → Add Local...**
4. **Important**: Consumers must add `ReactNativeRuntime` first, then module frameworks

**Pros:**
- ✅ Works immediately with current Package.swift files
- ✅ No changes needed to generated packages
- ✅ Simple for local/team distribution

**Cons:**
- ❌ Requires distributing all packages together
- ❌ Directory structure must be maintained

---

**Option 2: Git Repository Dependencies (Recommended for Remote/Public Distribution)**

For independent distribution of each package, publish to Git repositories and use URL-based dependencies.

**Update Package.swift for distribution:**

```swift
dependencies: [
    // Change from:
    // .package(path: "../ReactNativeRuntime")
    // To:
    .package(url: "https://github.com/yourorg/ReactNativeRuntime.git", from: "1.0.0")
],
```

**How to Distribute:**
1. Create Git repositories for each package:
   - `ReactNativeRuntime` → `https://github.com/yourorg/ReactNativeRuntime.git`
   - `ModuleProductsFramework` → `https://github.com/yourorg/ModuleProductsFramework.git`
   - etc.
2. Tag releases with semantic versions (e.g., `1.0.0`, `1.1.0`)
3. Update each module's `Package.swift` to use Git URLs
4. Consumers add packages via Xcode: **File → Add Package Dependencies → Add Package...**

**Pros:**
- ✅ Independent distribution of each package
- ✅ Version control and semantic versioning
- ✅ Works with Xcode's remote package support
- ✅ No directory structure requirements

**Cons:**
- ❌ Requires Git repositories for each package
- ❌ Need to manage versions and tags
- ❌ Requires updating Package.swift files before distribution

---

**Option 3: Hybrid Approach (Best of Both Worlds)**

Support both local (development) and remote (distribution) dependencies:

1. **For Development**: Keep relative paths (current setup)
2. **For Distribution**: Create a distribution script that:
   - Copies packages to a distribution folder
   - Optionally updates Package.swift files to use Git URLs
   - Creates a zip/tarball for distribution

**Example Distribution Script:**
```bash
# Create distribution package with Git URLs
./scripts/distribute-spm-packages.sh --mode=remote --git-url=https://github.com/yourorg
```

#### Consumer Integration Steps

**Local Distribution (Option 1):**

1. Copy `frameworks/ios/` folder to your project
2. In Xcode: **File → Add Package Dependencies → Add Local...**
3. Navigate to `frameworks/ios/ReactNativeRuntime` and add it
4. Repeat for each module framework (Products, Cart, PDP)
5. Import in code: `import React`, `import ModuleProductsFramework`

**Remote Distribution (Option 2):**

1. In Xcode: **File → Add Package Dependencies → Add Package...**
2. Enter Git URL: `https://github.com/yourorg/ReactNativeRuntime.git`
3. Select version: `Up to Next Major Version` from `1.0.0`
4. Repeat for each module framework
5. Import in code: `import React`, `import ModuleProductsFramework`

## 🏗️ Architecture

This monorepo uses **npm workspaces** to manage:
- **Apps** (`apps/*`) - Expo-based React Native modules that can be embedded in native apps
- **Packages** (`packages/*`) - Shared UI components, state management, and utilities

### Apps

- **`module-products`** - Products listing module
- **`module-cart`** - Shopping cart module  
- **`module-pdp`** - Product detail page module
- **`shell`** - Development shell app (for testing modules)

### Packages

- **`@pkg/core`** - API clients, hooks, and domain logic
- **`@pkg/state`** - Redux Toolkit store and slices
- **`@pkg/ui`** - Shared UI primitives (Header, Footer, Navigation)
- **`@pkg/products-ui`** - Products listing UI components
- **`@pkg/cart-ui`** - Cart UI components
- **`@pkg/pdp-ui`** - Product detail page UI components
- **`@pkg/homepage-ui`** - Homepage UI components

See [docs/PACKAGES.md](./docs/PACKAGES.md) for detailed package documentation.

## 🚀 First-Time Setup (For New Team Members)

> **⚠️ IMPORTANT**: This monorepo must be set up **FIRST** before setting up the native Android or iOS apps. The native apps depend on Verdaccio running and packages being published.

### Prerequisites

- **Node.js LTS** (>=20) - [Download](https://nodejs.org/)
- **npm** (comes with Node.js)
- **Git** (for cloning the repository)

### Step-by-Step Setup

Follow these steps **in order**:

#### Step 1: Clone and Install Dependencies

```bash
# Clone the repository
git clone <repository-url>
cd monorepo-expo-rn-ssr-csr

# Install all workspace dependencies
npm install
```

**Expected output**: All packages in `apps/` and `packages/` will have their dependencies installed.

#### Step 2: Start Verdaccio Registry

```bash
# Start Verdaccio (keep this terminal open)
npm run verdaccio:start
```

**Expected output**: You should see:
```
warn --- http address - http://localhost:4873/ - verdaccio/6.0.5
```

**⚠️ Keep this terminal running** - Verdaccio must stay running for native apps to install packages.

#### Step 3: Login to Verdaccio (First Time Only)

Open a **new terminal** (keep Verdaccio running in the first one):

```bash
# Navigate to the monorepo directory
cd monorepo-expo-rn-ssr-csr

# Login to Verdaccio
npm adduser --registry http://localhost:4873
```

**When prompted:**
- **Username**: Enter any username (e.g., `developer`)
- **Password**: Enter any password (e.g., `password`)
- **Email**: Enter any email (e.g., `dev@example.com`)

**Expected output**: `Logged in as <username> on http://localhost:4873/`

#### Step 4: Configure npm Scopes

```bash
# Configure npm to use Verdaccio for @app and @pkg scopes
npm config set @app:registry http://localhost:4873
npm config set @pkg:registry http://localhost:4873
```

**Verify configuration:**
```bash
npm config get @app:registry
npm config get @pkg:registry
```

Both should return: `http://localhost:4873`

#### Step 5: Publish All Packages to Verdaccio

```bash
# Publish all workspace packages to Verdaccio
npm run verdaccio:publish-all
```

**Expected output**: You should see packages being published:
```
✅ Published @pkg/core@0.1.0
✅ Published @pkg/state@0.1.5
✅ Published @app/module-products@0.1.8
✅ Published @app/module-cart@0.1.8
✅ Published @app/module-pdp@0.1.8
...
```

**⚠️ Important**: If you see errors about packages already existing, that's fine - it means they were already published.

#### Step 6: Verify Setup

```bash
# Check if packages are available in Verdaccio
npm view @app/module-products --registry http://localhost:4873
```

**Expected output**: Package metadata should be displayed.

**Or visit**: http://localhost:4873 in your browser to see the Verdaccio web UI.

### ✅ Setup Complete!

Your monorepo is now ready. You can now proceed to set up the native Android and iOS apps.

**Next Steps:**
1. **Keep Verdaccio running** (the terminal from Step 2)
2. Set up **Native Android App** (see its README)
3. Set up **Native iOS App** (see its README)

```bash
# 1. Make sure Verdaccio is running (Step 2 above)

#    cd js && npm install @app/module-products@latest
```

## 📦 Distribution

Modules are published to a local Verdaccio registry and consumed by standalone native Android/iOS apps.

### Publishing Modules

```bash
# Publish all packages at once
npm run verdaccio:publish-all

# Or publish individual packages
cd apps/module-products
npm run publish:verdaccio
```

### Consuming in Native Apps

1. Configure `.npmrc` in your native project to point to Verdaccio
2. Install packages: `npm install @app/module-products`
3. Bundle with Metro: `npm run bundle:products`
4. Load the bundle in your native app

See [docs/LOCAL_REGISTRY.md](./docs/LOCAL_REGISTRY.md) for detailed setup instructions.
